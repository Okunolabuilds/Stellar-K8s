# Documentation Build

> **Issue #1710** — Added a dedicated documentation build CI job and a local `make` target so the published site never diverges from a broken state.

## Overview

The documentation site is generated by [MkDocs Material](https://squidfunk.github.io/mkdocs-material/) from the `docs/` directory and `mkdocs.yml`.  
A dedicated CI workflow (`.github/workflows/docs-build.yml`) builds the site on every pull request or push that touches documentation sources, enforcing **strict mode** so any broken link, unrecognised anchor, or navigation warning fails the job.

## Local Usage

```bash
# Build the site once (strict mode, mirrors CI)
make docs-ci-build

# Serve the site with live-reload for local editing
make docs-serve
```

`make docs-ci-build` is the local equivalent of the CI job. It calls `mkdocs build --strict --verbose` and exits non-zero on any warning, giving contributors early feedback before opening a PR.

## CI Behaviour

| Trigger | What runs |
|---|---|
| PR / push touching `docs/**`, `mkdocs.yml`, or `requirements.txt` | Full strict build |
| `workflow_dispatch` | Full strict build |

The built `site/` directory is uploaded as a workflow artifact (`docs-site-<sha>`, retained 7 days) for preview review.

## Configuration

All MkDocs options live in `mkdocs.yml` at the repository root.  The `strict: true` key makes the configuration itself enforce strict mode; the `--strict` CLI flag in both the CI workflow and the Makefile provides a redundant safety net.

Python dependencies (mkdocs, mkdocs-material, plugins) are pinned in `requirements.txt`.
